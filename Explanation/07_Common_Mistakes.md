# 07 · Common Mistakes: GameplayLint

**Rule:** for every module, the mistakes that are easy to make here, **how to spot them, how to prevent them and how to debug them**. Mistakes that **actually happened in this project** are marked ⚠ caught; they are the real interview stories. Rule-code mistakes are added step by step in Phase 5 (S1–S4 below). The Data Validation pitfalls below come from Phase 2's source reading, and the design already guards against them.

Paths are relative to `Engine/`; `EVS.cpp` is `Plugins/Editor/DataValidation/Source/DataValidation/Private/EditorValidatorSubsystem.cpp`, and the other DataValidation files are in the same plugin.

---

## Foundation and pipeline (Phase 4)

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| ⚠ caught: **no `DefaultInput.ini`** in a hand-made project | The packaged smoke run logs "UEnhancedInputLocalPlayerSubsystem … does not have a valid PlayerInput object" (`09` F-5a) | Set the Enhanced Input player input and component classes, as Epic's templates do (`05` A9) | Grep the engine for the message (`EnhancedInputSubsystems.cpp:118`) and read the condition above it |
| A plugin module depends on another plugin's module that the `.uplugin` doesn't list | UBT warning "Plugin '…' does not list plugin '…' as a dependency …" (`UEBuildTarget.cs:1564–1579`); fails later in a project with that plugin off | List it under `"Plugins"` (`06` §5) | Read the warning: it names both modules |
| A lint module made `Runtime` | The game target tries to link `UnrealEd`/`DataValidation` and fails; or it builds and ships editor code | Every lint and bench module is `"Type": "Editor"` (`06` §4) | The game build log's compile list must show only `GameplayLintModule.cpp` from the project (`09` F-2) |
| The game module depends on a lint module | The isolation check fails: lint code compiles into the game | Dependency rule: packs → core → engine; the game knows nothing of the rules (`02` §3) | `grep GameplayLint Source/GameplayLint/GameplayLint.Build.cs` must find only the module's own name |
| ⚠ caught (portfolio audit): **a generated token committed with the config.** The default-on Android File Server plugin writes a random `SecurityToken` into `DefaultEngine.ini` on the first editor start | `git diff` shows an `[/Script/AndroidFileServerEditor.…]` block nobody wrote | Disable the plugin in the `.uproject` and delete the block (`05` A1, A9) | Diff the config before and after one editor start (`09` F-6) |
| ⚠ caught (portfolio audit): **a command-line switch the engine doesn't parse** (`-ExitAfterSeconds`, copied from another project's script) | Nothing visible: the switch is silently ignored | Before relying on a switch, grep the engine source for it; here it occurs nowhere in 5.8.4 | `grep -r ExitAfterSeconds Engine/Source Engine/Plugins` |
| ⚠ caught: **`sed -i` in Git Bash strips the CR from CRLF batch files** while editing them | `file Tools\*.bat` stops saying "with CRLF line terminators" | Re-add CRLF after any scripted edit; `.gitattributes` normalises on commit | `cat -A` shows `$` instead of `^M$` at line ends |
| Batch files saved with LF line endings | Odd `cmd.exe` parse errors, usually near labels or blocks | Save as CRLF; `.gitattributes` has `*.bat eol=crlf` | `file Tools\*.bat` shows "with CRLF line terminators" |
| Launching timed runs with `cmd /c start "" /wait /affinity …` | Never visible: it returns 0 even when the program failed (found by another portfolio project). Corrected here before any timed run | `pin_self` once in the runner, then `subprocess.Popen`, timeout, kill in `finally` (`05` A10) | Run a command that exits 3 through each method and compare the exit codes |
| Starting any UE job outside the queue | Another project's benchmark gets noisy; two compiles fight | Every build, commandlet and timed run goes through `tools\ue_queue.py` | `ue_queue.py status` shows who holds the machine |

## Steps S1–S4: fixtures, seeder, core, walker (Phase 5)

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| ⚠ caught: **a module that subclasses a validator without listing `DataValidation` itself**, relying on the core's public dependency | Compiles, then fails to link: `LNK2001 … UEditorValidatorBase::K2_ValidateLoadedAsset_Implementation` and three more (queue job `20261121_030734_92a7d8`, `09` S1–S4) | Every module that defines a rule or calls a validator's functions lists `DataValidation`, and its plugin lists the `DataValidation` plugin (the link rule, `02` §3) | The unresolved symbol names the class; find which module exports it (`DATAVALIDATION_API`) and check that module's dependency list |
| ⚠ caught (first S1–S4 baseline): **`+Key=` lines in a loose tag file** (`Config/Tags/GLSeed*.ini`). The `+` only means "append" in the layered config files; a loose file is read without ini symbol commands, so the engine saw a key named `+GameplayTagList` and loaded **no** corpus tag | The stock run logged 7,661 warnings at N = 1,000: "Invalid GameplayTag Fixture.Tag.00" even in the shared tables, which hold only permanent tags | Write one plain `GameplayTagList=(Tag="…")` line per tag (`ConfigCacheIni.cpp:2051, 2076–2096, 2216–2219`); `run_scan.py` now marks a run not ok if any permanent tag is reported invalid | Check a tag you know is declared: if the engine calls it invalid, the dictionary is the problem, not the data |
| ⚠ caught (code review): **`FParse::Value` stops at a comma** by default, so `-GameplayLintRules=GL.Data,GL.UB` became `GL.Data` and `-Paths=A,B` became `A` | No error: a configuration quietly runs fewer rules or folders | Pass `bShouldStopOnSeparator = false` for list values (`Parse.cpp:298`, `06` §18) | Log the parsed list once at start-up and compare it with the command line |
| ⚠ caught (code review): **`FFileHelper`'s default encoding writes UTF-16** as soon as a string holds a non-ANSI character (an em dash in a message is enough) | `json.load` fails with a decode error on one run only | Pass `EEncodingOptions::ForceUTF8WithoutBOM` for every file a script reads (`06` §15) | Look at the first two bytes of the file: `FF FE` is UTF-16 |
| ⚠ caught (code review): **an unreadable change list counted as an empty change**: the incremental run validated nothing and exited 0 | A wrong `-Changes=` path gives a green run | Unreadable input fails the run (`bChangesUnreadable`, `ProcessValidationResults` returns false) | Run once with a missing file and check the exit code is not 0 |
| ⚠ caught (code review): **`-Paths` was silently ignored with `-Changes`** | An incremental run checks assets outside the folder you named | Warn and drop `-Paths` when both are given; `run_scan.py` never passes both | Read the warning line; compare the report's asset list with the paths |
| ⚠ caught (code review): **an unknown `-GameplayLintDependents=` value was ignored**, so a typo meant the configured default | I2/I3 look identical to I1 | Unknown values log a warning that names the accepted ones | The report's `dependents_mode` says which mode really ran |
| ⚠ caught (code review): **mutating an already-mutated corpus** shifts the ground truth (M4 adds 100 twice; M1 finds no rows to remove) | Scores of the incremental batch don't add up | `-Mutate` refuses a corpus whose `DT_TargetsA` no longer has row `T30` | Re-seed from the seed, then mutate once |
| ⚠ caught (S4, before any rule existed): **assuming a generic iterator can't see inside `FInstancedStruct`**, which made a "held-out" category that the walker would find | Reading the iterator's source while writing the walker (S4) showed that it unwraps the payload; the walker test now checks a tag inside `Extra` | Read the iterator's source, not its header comment (`UnrealType.cpp:57–65`); the held-out kind is now a project's own two-field reference (`01` §7.1) | Write the walker test first: one value of each structural variant, and check every path is visited |
| ⚠ caught (citation check, S1–S4): **line numbers from a different copy of a header** (Phase 2 cited `DataValidationChangelist.h:62–95`; the 5.8.4 header has 52 lines) | A script that opens each cited file and line finds the symbol missing | Cite from the installed 5.8.4 tree only; re-check citations before each commit | `sed -n <line>p` the cited file |
| ⚠ caught (before the build): **a backslash in a `TEXT("…")` path** (`Tools\seed.py`): `\s` is not an escape sequence | MSVC warning C4129 "unrecognized character escape sequence", which breaks the 0-warning rule; the message shows `Toolsseed.py` | Write `\\` in C++ strings, or use `/` | Grep the source for `TEXT\("[^"]*\\[^\\nrt"]` |
| ⚠ caught (tooling): **shell here-documents and inline Python mangle backslashes**: `\r` in a doc table became a real carriage return, and `\s` collapsed | `git diff` shows `^M` in the middle of a line; a table cell lost its `Tools\` prefix | Write edit scripts as files and run them with `python -I`; scan every changed file for control characters before committing | `grep -c $'\r'` on LF files; `cat -A` |
| Setting a Blueprint's class-default values **before** compiling it | The values are missing after save: compiling made a new generated class and CDO | Compile first, then set the CDO's values, then save (the seeder's order, `05` C2) | Load the saved Blueprint and print the CDO value |
| A test-only validator left enabled | Every real scan runs it and reports `GL.Test.*` findings | `UGLTestRule::IsEnabled()` returns false; the test calls it directly | `F-3`-style: list the enabled validators in a scan log |
| Reading a Blueprint's components from its own construction script only | Components inherited from a parent Blueprint are never checked | Use `AActor::ForEachComponentOfActorClassDefault` (`06` §21) | A test with a component added in the parent only |

## Step S5: the first rules (Phase 5)

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| ⚠ caught (code review): **a rule test with no known-good case of the thing it checks.** The first UnknownTag test had only "no tags" as its clean case, so a rule that flagged *every* tag would have passed | Mutate the rule's condition and see whether a test fails | Every rule test has a near-miss case: a declared tag, a handle to a row that exists, a flat curve | Invert the rule's condition locally; the test must fail |
| ⚠ caught (code review): **fixed object names in the transient package** (`DT_TestRows`): a second run in the same editor session reconstructs the first run's live object in place | Only on a re-run in one session: odd stale state | Unnamed `NewObject`, or `MakeUniqueObjectName` | Run the test twice from the Session Frontend |
| Using `FindRow` to test whether a row exists | A warning in the log for every missing row, and the row struct type is needed | `GetRowMap().Contains(RowName)`, or `FindRow` with `bWarnIfRowMissing = false` (`DataTable.h:219`) (`05` F2) | Grep the log for "requested row … not in DataTable" (`DataTable.cpp:1094`) |
| A rule that loads assets in `AppliesTo` | Validation gets slow on assets the rule never reports on | `AppliesTo` reads `FAssetData` only (`06` §24) | Time `CanValidateAsset` separately |

## Step S6: the curve rule (Phase 5)

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| ⚠ caught (code review): **checking only key values for NaN**. Cubic interpolation also reads the tangents, so a NaN tangent makes every value between two keys NaN | `Eval` between keys returns NaN although every key value is finite | Check time, value, both tangents and both weights (`05` F2) | Evaluate the curve at the midpoints of its keys |
| ⚠ caught (code review): **"no keys" as the test for an empty curve**. A curve with no keys but a default value is a deliberate constant, and a NaN default value poisons every read | False alarms on constant curves; missed NaN defaults | `HasAnyData()` for "empty"; `IsFinite(DefaultValue)` for "broken" (`RealCurve.h:140–143`) | Print `GetNumKeys()` and `DefaultValue` together |
| ⚠ caught (code review): **reporting an external curve asset's keys on every asset that points at it** | Fifty errors for one bad `UCurveFloat`, none naming it | The curve asset reports its own keys, once; the owner names the external asset in its findings | Group findings by message; identical ones across many assets point to shared data |
| ⚠ caught (code review): **a curve asset or curve table that no rule checks**, because their curves are not `FRuntimeFloatCurve` properties | A NaN typed into a shared curve asset is never reported on it | Check `UCurveFloat::FloatCurve` and every `UCurveTable` row directly | Validate the curve asset alone |
| ⚠ caught (code review): **guessing the meaning of a misspelt annotation** (`LintMonotonic="Descending"` was read as "Increasing") | Correct curves flagged, broken ones passed | Accept the two documented values; report anything else | Grep the project for `LintMonotonic=` and compare the values |
| ⚠ caught (code review): **two findings for one defect** (an infinite key also counted as a reversal) | Counts per defect above 1 in the score | Stop after the non-finite finding; check the direction on finite data only | The score's per-cell counts |
| A word inserted into a localised message with `FText::FromString` | Translations show one English word in a translated sentence | One complete `LOCTEXT` message per case | Run the editor with a test culture |
| ⚠ caught (S6, before the build): **a fixture change that breaks an older test**. Adding a second `LintMonotonic` curve broke the S4 walker test, which counted exactly one | The test name says "exactly one" | After a fixture change, grep the tests for the changed field's annotation | Run the whole `GameplayLint` test filter, not only the new test |

## Step S7: the UpdateBudget pack (Phase 5)

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| ⚠ caught (S7, first test run): **a UObject kept only in a raw C++ pointer across a Blueprint compile.** The compile ends with a garbage collection (`BlueprintCompilationManager.cpp:423–427`), so the test's rule objects were freed, and the next `ValidateLoadedAsset` crashed with an access violation (queue job `20261121_062431_018fb5`) | A crash inside engine code, with your function one frame below; an address like `0xffffffffffffffff` | Hold such objects with `TStrongObjectPtr` (or a `UPROPERTY` of a referenced object) whenever any call in between can collect garbage | The call stack names your caller; ask whether anything between creation and use can collect garbage |
| ⚠ caught (code review): **"never ticks" decided from `bStartWithTickEnabled` alone**. An auto-activating component's tick is enabled by `Activate`, so the first version called a ticking client broken (an Error) and missed per-frame tickers | A rule's verdict disagrees with what the component does in a running game | One shared `StartsTicking` that includes `bAutoActivate` (`06` §25) | Spawn the actor in a test world and read `IsComponentTickEnabled()` |
| ⚠ caught (code review): **one misconfigured client reported by two rules** (wrong group *and* never ticks) | Two findings for one seeded defect | A rule skips what another rule owns: the group is not compared for a client that never ticks | The score's wrong-rule count |
| ⚠ caught (code review): **resolving settings paths in the innermost loop** | Rule time grows with templates × paths × rules | Resolve once per checked asset (`FClasses`) | `check_times_ms` per rule |
| Expecting `+Array=` in `DefaultEditor.ini` to *add to* the constructor's defaults | Default entries (here UE5-UpdateBudget's own client class) disappear | A config array with entries replaces the constructor's list (`ProcessArrayProperty`, `EmptyAndAddValues`); repeat the defaults in the ini if they must stay | Print the settings object after start-up |
| A rule pack that includes another module's private headers, or a test that needs them | Build errors as soon as the other module moves code; hidden coupling | Name classes by path (`FSoftClassPath`); tests find rule classes by path too (`05` F4) | `grep -r "Private/" *.Build.cs` |

## Data Validation: pitfalls found in Phase 2 (designed against)

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| Overriding the **5.0–5.3 validator signatures** found in older tutorials | `ensure` "running deprecated validation path" (`EditorValidatorBase.cpp:37–50`); deprecation warnings at compile time | Override `CanValidateAsset_Implementation(const FAssetData&, UObject*, FDataValidationContext&)` and the matching `ValidateLoadedAsset_Implementation` (`01b` §2) | Compile with warnings as errors; the 0-warning rule catches it |
| Returning `NotValidated` after `CanValidateAsset` said yes | `ensure` "did not return a validation result from native validation path" (`EditorValidatorBase.cpp:58`) | The rule base class always ends with pass or fail; rules only report (`02` §4.1) | Break on the ensure; check which branch returned early |
| Calling `AssetPasses` after reporting an error | `ensure` "AssetPasses called after errors were reported" (`:152`) | Same: the base class decides once, after the rule ran | Same |
| Expecting a rule to run on an asset whose `IsDataValid` failed | The rule's finding is missing, but the asset is "Invalid" for another reason | Know the order: class check first, validators only if it didn't fail (`EVS.cpp:657–663`). The corpus measures masking | Validate the asset alone; read every message, not only yours |
| Testing a tag rule only on save | Unknown tags seem undetected on save but detected in CI, or the reverse | On-save validation doesn't load assets, so load warnings don't appear there (`EVS.cpp:1167`) | Compare a fresh-load commandlet run with an on-save run on the same asset (H3) |
| Using `FGameplayTag::IsValid()` as "the tag exists" | Unknown tags pass the check | It only tests for `None` (`GameplayTagContainer.h:138–141`); ask the manager: `RequestGameplayTag(Name, false)` | Log both results for a deliberately unknown tag |
| Trusting the stock commandlet's exit code in CI | A corpus with failing assets returns 0; an unrelated logged error returns 1 | Gate on the per-asset results (the child commandlet's report and `-FailOn`), not the process code (`01b` #7, B-2) | Run once on a known-bad asset and print the exit code |
| Expecting "Validate Assets and Dependencies" to check the **referencers** | A changed table's victims are never checked | It validates what the selection references, not what references it (`DataValidationModule.cpp:230–232`) | Read the menu tooltip; test with a removed row |
| Expecting changelist validation to re-check victims of a **modified** asset | Removing a row passes pre-submit; the break appears later | The engine adds referencers only of **deleted** packages (`EVS.cpp:1492–1516`); rules add the rest through `GetAssetsToValidateFromChangelist` (`02` §6.2) | Compare an incremental run with a full scan after the same change (SC6) |
| Expecting the registry to know about a handle with a **null table** | The precise dependent query misses it | Such handles aren't recorded as searchable names (`DataTable.cpp:1117`); the per-asset check still finds them | Inspect `GetDependencies(…, SearchableName)` for the asset |
| An `ExcludedDirectories` entry that is too short | Unrelated folders silently stop being validated | It is a **substring** match (`EVS.cpp:1197–1208`): use full, unique paths such as `/Game/Developers/` | Log `IsPathExcludedFromValidation` for a few paths |
| A validator that **modifies** the asset it checks | Packages become dirty on save or pre-submit; changes nobody asked for | Checks are read-only; only a user-clicked fixer may change data (`02` §8) | Look for dirty packages after a validation run |
| Unattended changelist validation while the registry is still scanning | The process ends with a Fatal error (`EVS.cpp:1350–1355`) | Wait for the registry first (the stock commandlet's `WaitForAssetRegistry`) | The log line names the cause |
